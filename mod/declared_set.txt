# mod/declared_set.txt -- the hookable set docs/mod-interface.md section 1
# declares: the DS addresses the port generates an indirection (a slot) for.
# This file is the single source of truth the generators read; section 1 is
# the prose account.
#
# One row per address, tab separated:
#   address   the even function start, as aletheia's `address:` line spells it
#   function  the aletheia function name
#   region    arm9, or the overlay id the address lives in
#   mods      the example mods that need the address, comma separated:
#             nuzlocke, soullink, nuzlocke-soullink, multiplayer
#             An empty fourth column means no example mod names the address;
#             the address is declared because the event catalogue of
#             docs/mod-events.md, section 1, binds an event or an override to
#             it.  The owner asked for these concepts to be coverable.
#
# A reader splits each line on tabs; `#` starts a comment.  tools/bootlink.py
# takes the arm9 rows and tools/ovlink.py takes the overlay rows; both emit
# the slot of section 2.
#
# The set grew from 44 rows to 180 when docs/mod-events.md, section 1, was
# rebuilt from the game's own command tables: the field script VM's 609-entry
# table at d_0217062C (entry points SCRIPT_SYS_CreateVm 0x02158BFC and
# SCRIPT_SYS_Main 0x0215882C) and the battle effect VM's 78-entry table at
# 0x02209E88 (entry point BTLV_EFFVM_Create 0x021F93F4).  The field VM's
# opcode-to-handler map is aletheia's tools/assets/scripts.py, OPERAND_WIDTH;
# the battle effect VM's handler list is layout/data_objects.json, the object
# g_02209E88.  The handler names are aletheia's per-packet manifests under
# layout/matched/**/pkt_*.json.
#
# The set grew from 180 rows to 193 when progress/EVENT_SURVEY.md was folded
# into the catalogue: 3 new events (CALENDER_OverlaySequenceEvent,
# FIELDMAP_AddZoneNpcs, GTSNEGO_DISP_StartTrade) and 10 new override points
# (BTL_SERVER_FLOW_CalcMoveDamage, BTL_CALC_CalcBaseDamage,
# BTL_CALC_RollCriticalHit, BTL_SERVER_FLOW_RollCriticalCapture,
# FIELD_FLASH_Apply, ITEMMENU_PrintMoney, SODATEYA_ApplyMasudaMethod,
# SODATEYA_RollNature, SODATEYA_RollAbilitySlot, SODATEYA_GrantExp).  The 91
# data tables and the 34 state entries the survey adds need no slot and are
# not declared here (docs/mod-events.md, sections 1 and 4).
#
# Every row was checked against aletheia's per-packet manifests under
# layout/matched/ (pkt_*.json), revision 80f06a261e8731f2db94c1a66627bb351ad47673,
# not copied from the section 1 table.  All 193 rows match a manifest function
# name and region.  One address is shared by two overlays that occupy the same
# RAM window: 0x021C5200 is BTL_SERVER_FLOW_ProcFaintRewards in ov093 and
# ZUKAN_DETAIL_FORM_SignalAnimDone in ov208.  The declared row is the ov093
# function; the overlay id disambiguates, the bare address does not.
#
# The rows below are sorted by region, then by address.  The 44 original rows
# are kept unchanged; the rest are new.  State accessors that a mod
# reads and writes through an accessor, and that no event or override binds,
# are not declared here: docs/mod-events.md, section 4, lists them, and
# docs/mod-interface.md, section 4, explains why an accessor needs no slot.
#
